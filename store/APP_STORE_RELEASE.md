## Build and signing

From the Flutter project root:

```sh
python3 tools/build_app_store_release.py --unsigned
```

This runs analyze/tests and creates `build/ios/archive/Runner.xcarchive` for technical inspection. It is not an installable/uploadable IPA. `tools/check_ios_archive.py` checks the archive's bundle ID, SDK/minimum OS, ARM64 binaries, manifest inventory, forbidden permissions/background modes, policy asset, debug symbols and missing Maps configuration without printing the key. Results: `build/app-store/archive-validation.json`. No passwords or certificates are generated by this tool.

The updated Apple Developer Program License Agreement was accepted on November 6. Automatic distribution export then succeeded. The locally verified App Store IPA is `build/ios/ipa/lando.ipa` (version 1.0.0, build 1). Signature, App Store provisioning, bundle ID and profile expiration checks passed; see `build/app-store/ipa-validation.json`. Nothing has been uploaded. The signed IPA is for App Store Connect distribution and TestFlight, not direct installation on an arbitrary device.

For a distribution IPA, first sign into the correct Apple Developer Program team in Xcode Settings -> Accounts, open `ios/Runner.xcworkspace` and confirm Signing & Capabilities for Runner. Keep automatic signing and verify the bundle ID/team. Then run:

```sh
python3 tools/build_app_store_release.py
```

`ios/ExportOptions.plist` exports locally for App Store Connect with team `C2M32YF6V7`; it does not upload. Change the team only if this app belongs to another Apple team, and keep the Xcode project and export file consistent. A paid program membership, authorized distribution certificate/private key and App Store provisioning are required for distribution. A local Apple Development identity alone is insufficient. Do not revoke existing certificates to fix signing. If automatic export needs authentication, use Xcode Organizer -> Distribute App -> App Store Connect to resolve it and choose export; validate before uploading.

For subsequent uploads, increase the build number in `pubspec.yaml` (for example `1.0.0+2`) before rerunning the release script. An Android upload does not consume an Apple build number. Do not upload a synthetic preview or integration-test build; release uses `lib/main.dart`.

## Downloaded model review

The app bundles its native llama runtime. Only the pinned, hash-verified GGUF weights are downloaded into the app container. These are data for the existing property assistant, not executable updates or plugins. We explain that in review notes; Apple decides whether the implementation complies with Guideline 2.5.2. Review download size/consent, memory behavior and the model's Apache 2.0 license. Do not remotely swap the pinned model after review or claim blanket approval for all downloadable AI models.

## Recreate screenshots

Use an isolated simulator (the test writes only a synthetic property to in-memory SQLite). Example:

```sh
LANDO_SCREENSHOT_DEVICE=iphone flutter drive --driver=test_driver/app_store_driver.dart --target=integration_test/app_store_smoke_test.dart -d IPHONE_SIMULATOR_ID
LANDO_SCREENSHOT_DEVICE=ipad flutter drive --driver=test_driver/app_store_driver.dart --target=integration_test/app_store_smoke_test.dart -d IPAD_SIMULATOR_ID
python3 tools/prepare_ios_store_assets.py
```

The asset helper requires Pillow and converts native capture encoding to opaque 8-bit RGB without changing the displayed content. The current iPhone screenshots are 1320 × 2868; iPad screenshots are 2064 × 2752. Native SDK text, Keychain save/delete and SQLite backup/restore are checked in the same smoke test. Real Google address search and Qwen download/inference/research have a separate `integration_test/ios_assistant_search_test.dart` test. No cloud AI credentials are used by these tests.

### Swift package deployment synchronization

Flutter 3.47.5 can regenerate `FlutterGeneratedPluginSwiftPackage` with iOS 15 while the native Qwen runtime requires 16.4. Runner's project and target configurations now explicitly agree on 16.4. The release script configures Flutter, synchronizes only the generated app package with that minimum, and uses Xcode directly for archive/export. The Xcode framework-prepare pre-action also runs `ios/scripts/sync_package_deployment.sh`. Dependency packages and the installed Flutter SDK are not modified. Prefer this release script to a raw `flutter build ipa` with the affected Flutter version; reevaluate the workaround when upgrading Flutter.
